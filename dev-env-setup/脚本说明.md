# 本目录脚本说明

幂等的运维 / 开发环境脚本。除本文档和 README 外，可执行脚本都在本目录（`dev-env-setup/`），互相从 GitHub raw 拉兄弟文件，所以不拆成多个工具目录。

仓库是 public，**不放 API Key**。默认分支 `main`。raw 基址：

`https://raw.githubusercontent.com/idlm/CommonUserScripts/main/dev-env-setup`

一键 curl / wget 见 [`README.md`](README.md)。

```
dev-env-setup/
├── README.md                 # curl / wget 一键说明
├── 脚本说明.md               # 本文件
├── setup.sh                  # 本目录脚本清单入口
├── setupV10.sh               # 一键安装 v1.0 入口
├── setupv11.sh               # 一键安装 v1.1 新机引导入口
├── git-autosync.sh           # Git 双向自动同步
├── github-ssh-push.sh        # GitHub SSH / GPG 密钥 + 推送
├── install-ai-agents.sh      # 安装 Claude / Codex / Gemini / zcf
├── install-android-env.sh    # 安装 JDK 17 + Gradle + Android SDK
├── install-full-env.sh       # 交互式一键安装(基础/APK/AI CLI+CPA/清理)
└── update-env-snapshot.sh    # 刷新 README 环境快照
```

脚本均可重复执行：已完成的步骤会跳过，不会无故覆盖已有密钥或已安装组件。

## 总览

| --- | --- | --- | --- | --- |

| `github-ssh-push.sh` | 生成本机 SSH 密钥、配 git、推送 | `bash github-ssh-push.sh` | 否 | 否（交互） |
| `install-ai-agents.sh` | 安装 AI Agent CLI | `bash install-ai-agents.sh` | 是 | 否 |

未克隆仓库、只想远程跑时：

```bash
# v1.0 分级子菜单
bash <(curl -fsSL https://raw.githubusercontent.com/idlm/CommonUserScripts/main/dev-env-setup/setupV10.sh)

# v1.1 新机引导(推荐)
bash <(curl -fsSL https://raw.githubusercontent.com/idlm/CommonUserScripts/main/dev-env-setup/setupv11.sh)

# 本目录脚本清单
bash <(curl -fsSL https://raw.githubusercontent.com/idlm/CommonUserScripts/main/dev-env-setup/setup.sh)

# 直接跑某个脚本
curl -fsSL https://raw.githubusercontent.com/idlm/CommonUserScripts/main/dev-env-setup/setup.sh \
  | bash -s -- install-android-env

# 只看有哪些脚本
curl -fsSL https://raw.githubusercontent.com/idlm/CommonUserScripts/main/dev-env-setup/setup.sh \
  | bash -s -- --list
```

本地已克隆时：

```bash
cd CommonUserScripts/dev-env-setup
bash setup.sh                 # 交互菜单
bash setup.sh --list          # 列出脚本
bash setup.sh git-autosync    # 按名字执行
bash <脚本名>.sh              # 不经入口，直接跑
```

可用环境变量 `RAW_BASE` 覆盖下载源，默认是本仓 `main` 下本目录的 raw 地址。兄弟脚本与入口同目录，路径里 **没有** `/scripts/`。

## 各脚本详解

### `setupV10.sh` / `setupv11.sh` — 一键安装两个入口

两者并存，互不覆盖：

| 版本 | 入口 | 体验 |
| --- | --- | --- |
| v1.0 | `setupV10.sh` → `install-full-env.sh` | 主菜单进组，组内再单装 |
| v1.1 | `setupv11.sh` | 预检磁盘/权限 → 选方案 → 自定义勾选 → 确认清单 → `[n/N]` 总进度 + wget 进度条 |

v1.1 方案：`new`(新机推荐，不含清理)、`base`、`apk`、`ai`、`custom`、`clean`。非交互：`--yes --profile apk` 或 `--items nano,claude,grok`。

`setupV10.sh` 查找顺序：与自身同目录的 `install-full-env.sh` → `$LOCAL_SCRIPTS_DIR` → `$RAW_BASE/install-full-env.sh`。

---

### `setup.sh` — 本目录脚本清单入口

不负责具体安装或同步，只做两件事：

1. 列出可执行脚本
2. 从 GitHub raw 下载对应文件到临时目录，校验 shebang 后交给 bash

设计成「curl 进来就能用」，所以即使用户本机没有克隆本仓库，也能选脚本执行。下载失败（404、空内容、不是 `#!` 开头）会直接中止，避免把 HTML 错误页当脚本跑。标记为需要 root 的脚本，在非 root 下会提前退出。

```bash
bash setup.sh              # 菜单，输入序号
bash setup.sh --list       # 只列出
bash setup.sh --help
bash setup.sh github-ssh-push
```

可选名字：`install-android-env`、`install-ai-agents`、`github-ssh-push`、`git-autosync`、`update-env-snapshot`、`install-full-env`、`setupV10`、`setupv11`。

### `git-autosync.sh` — Git 双向自动同步

给无人值守环境用：把目标仓库（默认当前目录，可用 `REPO_DIR` 覆盖）和 GitHub 上的 `origin/main` 对齐。

| 两端状态 | 行为 |
| --- | --- |
| 一致 | 什么都不做 |
| 本地有改动（含删除） | `git add -A` → 提交 → 推送 |
| 只有远端领先（含删除） | 快进拉取，远端删除会落到本地 |
| 分叉且不冲突 | `git rebase` 后推送 |
| 分叉且冲突 | `rebase --abort` 回到同步前状态，记日志并非 0 退出 |

额外约束：

- 只在配置的分支上跑（默认 `main`），当前分支不一致会中止
- 仓库正处于 merge / rebase / cherry-pick 时拒绝介入
- 提交前扫描暂存文件名，命中 `.env`、`*.pem`、`*.key`、`id_rsa` / `id_ed25519`、`.netrc`、`credentials` 等则取消暂存并退出，避免密钥进 Git 历史
- 用文件锁防并发，上一轮没跑完时本轮直接跳过
- 日志超过 1 MB 只留后半段

```bash
bash git-autosync.sh
```

常用环境变量：

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `REPO_DIR` | `$PWD` | 仓库路径 |
| `BRANCH` | `main` | 同步分支 |
| `REMOTE` | `origin` | 远端名 |
| `SSH_KEY` | `$HOME/.ssh/id_ed25519_github` | 推送用私钥 |
| `LOG_FILE` | `/var/log/git-autosync.log` | 日志 |
| `FORCE_REMOTE_WINS` | `0` | 置 `1` 时 rebase 冲突会丢弃本地提交、强制与远端一致（不可恢复，默认关） |

自行配 cron 即可，例如每 15 分钟一次。没有 systemd 的环境需要另想办法让 cron 在登录后拉起。不要对着本 public 仓无脑开 autosync。

### `github-ssh-push.sh` — GitHub 密钥 + 推送

交互脚本，把「生成密钥 → 你去网页粘贴 → 验证 → commit / push」串成一条直线，**不会自动把公钥上传到 GitHub**。

流程：

1. 检查 `git` / `ssh` / `ssh-keygen`
2. 询问 GitHub 用户名和邮箱
3. 生成（或复用）`~/.ssh/id_ed25519_github`，并校验公钥是单行 OpenSSH 格式
4. 写入 `~/.ssh/config`，探测 22 端口，不通则改走 `ssh.github.com:443`
5. 在终端打印公钥，等你到 [GitHub SSH keys](https://github.com/settings/ssh/new) 添加
6. 验证 `git@github.com` 能认证
7. 配仓库级 `user.name` / `user.email`，HTTPS origin 会改成 SSH，然后确认后 `add` / `commit` / `push`

可选 `--gpg`：额外生成 GPG 签名密钥，打印装甲公钥让你加到 GitHub，并打开本仓库的 `commit.gpgsign`。

```bash
bash github-ssh-push.sh              # 默认只做 SSH
bash github-ssh-push.sh --gpg        # 额外做 GPG 提交签名
bash github-ssh-push.sh --show-key   # 只展示已有公钥
bash github-ssh-push.sh -u NAME -e MAIL -r REPO -y
```

提交前同样会扫疑似密钥文件。危险步骤（提交、推送）要明确确认；`--yes` 可跳过，仅建议自动化使用。

### `install-ai-agents.sh` — 安装 AI Agent CLI

用 npm 全局安装四个 CLI，并保证 Node.js 主版本 ≥ 22（不够就走 NodeSource 装）：

| 键名 | 命令 | npm 包 | 说明 |
| --- | --- | --- | --- |
| `claude` | `claude` | `@anthropic-ai/claude-code` | Anthropic 官方 Claude Code |
| `codex` | `codex` | `@openai/codex` | OpenAI 官方 Codex CLI |
| `gemini` | `gemini` | `@google/gemini-cli` | Google 官方 Gemini CLI |
| `zcf` | `zcf` | `zcf` | Claude Code 快速配置（也可用 `npx zcf` 免安装） |

已安装的组件默认跳过；`--force` 才重装 / 升级。需要 root（全局 npm 安装，且可能补装 Node）。

```bash
bash install-ai-agents.sh                 # 四个都装
bash install-ai-agents.sh claude codex    # 只装指定的
bash install-ai-agents.sh --list
bash install-ai-agents.sh --force gemini
```

环境变量：`NPM_REGISTRY`（默认官方源）、`NODE_MAJOR_MIN`（默认 22）。

### `install-android-env.sh` — 安装 APK 编译环境

在 Debian 上装一套能编 Android 14 APK 的工具链，步骤幂等：

1. OpenJDK 17、unzip、wget
2. Gradle 8.7 → `/opt/gradle-8.7`
3. Android cmdline-tools → `/opt/android-sdk/cmdline-tools/latest`
4. 接受 SDK 许可
5. platform-tools（adb）
6. build-tools 34.0.0
7. platform android-34
8. 写入 `/etc/profile.d/android.sh`（`ANDROID_HOME` 和 PATH）

```bash
bash install-android-env.sh
# 当前终端立刻生效：
source /etc/profile.d/android.sh
```

需要 root。`gradle` / `adb` 只在登录 shell 的 PATH 里；cron、`bash -c`、CI 要用绝对路径，或先 `source /etc/profile.d/android.sh`。

### `install-full-env.sh` — 交互式一键安装

本机菜单入口。1 / 2 / 3 是大类，进去后可以再单选某一项；5 装全部项目，6 清系统和软件缓存。

1. 基础软件：进入后单选 `nano` / `htop` / `btop` / `screen`，或装本组全部
2. APK 编译环境：进入后单选 JDK / Gradle / cmdline-tools / adb / build-tools / platform，或装本组全部
3. AI CLI：进入后单选 `zcf` / `claude` / `gemini` / `codex` / `grok` / **cpa**，或装本组全部
5. 安装全部项目（1+2+3，不含清理）
6. 清理系统垃圾与软件缓存（apt / npm / pip / go）

**cpa 是 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)**，不是 npm 上那个同名包。Linux 官方安装命令：

```bash
curl -fsSL https://raw.githubusercontent.com/router-for-me/cliproxyapi-installer/refs/heads/master/cliproxyapi-installer | bash
```

`api.github.com` 匿名限额打满时，官方安装器失败，脚本会解析 `releases/latest`，直下 `CLIProxyAPI_<ver>_linux_amd64.tar.gz`，装到 `~/cliproxyapi/`，并在 `/usr/local/bin` 链出 `cpa` 和 `cli-proxy-api`。

grok 走 `https://x.ai/cli/install.sh`。若本机 DNS 把 `x.ai` 解析错，脚本用 `--resolve x.ai:443:104.18.18.80` 绕过。

```bash
bash install-full-env.sh                 # 主菜单
bash install-full-env.sh 3               # 进入 AI CLI 子菜单
bash install-full-env.sh claude grok cpa # 只装指定组件
bash install-full-env.sh 5               # 安装全部项目
bash install-full-env.sh 6               # 清理垃圾与缓存
bash install-full-env.sh --force grok    # 强制重装 grok
```

需要 root。CPA 装完后还要自己登录（`cpa --claude-login` / `--codex-login` / `--login`），脚本不代登。

`run_sibling` 查找顺序：与自身同目录 → `$LOCAL_SCRIPTS_DIR` → `$RAW_BASE/<脚本名>`。

### `update-env-snapshot.sh` — 刷新 README 环境快照

采集本机数据，只改目标 `README.md` 里这一对标记之间的内容，标记外的人工维护部分不动：

```
<!-- SNAPSHOT:START -->
...自动生成的表格...
<!-- SNAPSHOT:END -->
```

采集内容包括：时区与运行时长、发行版 / 内核、CPU / 内存 / 磁盘、JDK / Gradle / Android SDK / Go / Node / Python / Git 版本、境内外出口 IP、内网地址、cron 是否在跑、最近一次 git-autosync 日志。

策略：

- 单项采集失败不中断整轮；版本号等本地字段失败会写成 `—`
- 出口 IP、同步日志这类网络字段失败时，回退到 README 里上次的有效值，并标记为降级采集（时间戳也保持旧值，避免「时间是新的、数据是旧的」）
- **自己不 git commit / push**，交给 `git-autosync.sh`，避免两个脚本抢索引锁
- 内容没变化就不写文件，不产生空提交

```bash
bash update-env-snapshot.sh
```

环境变量：`REPO_DIR`（默认 `$PWD`）、`README`、`LOG_FILE`（默认 `/var/log/env-snapshot.log`）、`SYNC_LOG`、`CURL_TIMEOUT`。

目标 README 必须先放好 `SNAPSHOT` 标记，否则脚本会退出。不要把别人机器上的 SNAPSHOT（IP、主机名）当成你的环境。

## 脚本之间怎么配合

```
github-ssh-push.sh     配好 SSH 密钥和 origin
        │
        ▼
git-autosync.sh        周期：本地改动推上去，远端改动拉下来
        ▲
        │ 不自己推送，只改 README 标记区块
update-env-snapshot.sh 采集环境，写进 README

install-full-env.sh
        菜单：1/2/3 大类可再单选；5 安装全部项目；6 清理垃圾与缓存
        内部会调用 install-android-env.sh 与 install-ai-agents.sh

setupv11.sh
        自包含安装实现（v1.1）

setup.sh
        远程或本地的统一入口，按名字调用上面这些脚本
```

不要和 autosync 同时手动 `git add` / `commit`，容易撞锁或分叉。

## 建议的 cron 与日志（需自行配置）

| 项目 | 建议值 |
| --- | --- |
| 同步 | `*/15 * * * *` → `git-autosync.sh` |
| 快照 | `9 3 * * *` → `update-env-snapshot.sh` |
| 同步日志 | `/var/log/git-autosync.log` |
| 快照日志 | `/var/log/env-snapshot.log` |
| SSH 密钥 | `$HOME/.ssh/id_ed25519_github` |
| SSH 通道 | 优先 `github.com:22`，不通则 `ssh.github.com:443` |

两份日志都超过 1 MB 时截断，只保留后半。宿主机被挂起期间 cron 不触发，恢复后是否补跑取决于 cron 实现。

## 直接调用示例

```bash
# 装 Android 编译环境
bash install-android-env.sh && source /etc/profile.d/android.sh

# 交互式一键安装(含 grok + CLIProxyAPI)
bash install-full-env.sh

# 只装 AI CLI(不含 grok / CPA)
bash install-ai-agents.sh

# 第一次对接 GitHub
bash github-ssh-push.sh

# 手动跑一轮同步 / 快照（一般交给 cron）
bash git-autosync.sh
bash update-env-snapshot.sh
```
